# 문앞지킴 주민용 모바일 웹 · FE-3

## 텔레그램 연결 (U07)

로그인 후 `내 정보 → 텔레그램 알림 설정`에서 연결·상태 확인·취소·해제를 할 수 있습니다. 연결 버튼으로 서버의 일회용 링크를 발급받고 봇에서 Start를 누르면, 웹에서 5초마다 서버 상태를 조회해 연결 완료를 표시합니다. 새 링크를 발급하면 이전 링크는 무효가 됩니다. 페이지를 다시 열어 링크가 없으면 새로 발급받을 수 있습니다. 예시 데이터 모드는 실제 봇에 연결하지 않습니다.

실제 연결에는 백엔드의 `TELEGRAM_BOT_TOKEN`과 `TELEGRAM_BOT_USERNAME` 설정이 필요합니다. 발급 오류 503은 설정을 확인하고, 이미 연결됐다는 409는 상태를 다시 확인한 뒤 필요하면 기존 연결을 해제합니다. 주의 알림 설정은 별도 후속 기능입니다. 아래 FE-3·FE-5 기록은 당시 범위를 설명합니다.

이창현 담당인 로그인(U01), 이벤트 목록(U03)·상세(U04), 상황 응답, 오탐 신고(U05)·접수 완료(U06)를 구현합니다. React·JavaScript·Vite와 React Router를 사용하며 화면 기준 폭은 **360~430px**, 최대 폭은 430px입니다.

화면과 앱 전용 스타일은 CSS Modules를 사용합니다. 해당 JSX 옆의 `*.module.css`, 재사용 스타일은 `common.module.css`와 `Button.module.css`, 앱 레이아웃은 `App.module.css`에서 관리합니다. `components/ui/`에는 shadcn/ui의 구성 방식을 바탕으로 조정한 JavaScript Button·Input·Textarea·Card·Badge를 두고, 부품 내부에서만 Tailwind 클래스를 사용합니다.

회색 팔레트와 테마 변수는 `shadcn.css`, 글꼴·기본 초기화·접근성 기본값은 `global.css`에서 관리합니다. Tailwind CSS 3.4와 PostCSS를 Vite에서 연결하고 `corePlugins.preflight: false`로 전체 화면에 대한 Preflight 초기화를 비활성화했습니다. 네트워크 제한으로 로컬 캐시에 있는 버전을 설치했으며, 클래스 조합·버튼 변형·`asChild` 처리는 `lib/`와 UI 부품의 로컬 구현을 사용합니다. shadcn CLI로 생성한 원본과는 차이가 있습니다.

작업 기준과 UI/UX 반영·검증 기록은 작업 루트의 `docs/villa-guard-front-UIUX-작업-기준.md`에서 확인할 수 있습니다. 주민용 5개 화면의 카드·간격·처리 상태 표시를 정리한 1차안이 반영되어 있습니다. Dribbble 원본 대조와 실제 브라우저 확인은 아직 완료하지 않았으며, 자세한 변경·검증 범위는 해당 문서 10절에 기록했습니다.

```bash
npm ci
npm run dev
```

개발 서버 주소에서 `예시 데이터로 둘러보기`를 누르면 서버 없이 흐름을 확인할 수 있습니다. 데모는 화면에 항상 표시되며 데이터는 현재 브라우저 탭의 `sessionStorage`에만 저장됩니다. 실제 신고·알림은 전송하지 않습니다. 실제 로그인 실패나 API 오류가 데모 모드로 자동 전환되지 않습니다.

실제 서버를 사용할 때는 `.env.example`을 `.env.local`로 복사하고 `API_PROXY_TARGET`을 설정합니다. 기본값은 `http://localhost:8080`입니다. 개발 서버가 `/api` 요청을 전달합니다. API 준비 상태는 저장소 코드와 확인해야 하며, 명세를 따른 호출 코드를 작성한 것이 서버 연동 검증 완료를 뜻하지 않습니다.

배포 시 `/api`를 백엔드로 전달하고 나머지 화면 경로를 `index.html`로 연결해야 합니다. 별도 API origin을 쓰려면 `VITE_API_BASE_URL`과 서버 CORS 설정이 필요합니다. 텔레그램 알림 경로 `/events/{event_id}`의 직접 접근·새로고침도 SPA fallback이 필요합니다. 운영자 연락처가 확정되면 `VITE_OPERATOR_PHONE`을 지정합니다.

실제 통합 배포는 `docs/deploy.md`의 EC2 nginx 구성을 따릅니다. `VITE_API_BASE_URL`을 비워 두면 같은 출처의 `/api`를 사용하므로 별도 CORS 설정이 필요 없습니다. nginx의 `try_files`로 이벤트 주소 직접 접근·새로고침도 `index.html`에 연결합니다. Vercel 배포는 ‘예시 데이터로 둘러보기’를 통한 데모 확인용이며 HTTP 백엔드와의 실제 통합 배포로 사용하지 않습니다.

```bash
npm run lint
npm test
npm run build
```

자동 검사는 인증 헤더·401 처리·API 오류, 실제 토큰의 탭 단위 보관·로그아웃·기존 영구 토큰 삭제·데모 격리, 월말·연말·윤일의 KST 날짜 경계와 쿼리 인코딩, 열람/응답 구분, 신고와 NORMAL 응답 동시 저장, 중복 신고·응답 잠금 등을 확인합니다. 브라우저에서 360·390·430px의 줄바꿈·터치·키보드 포커스와 실제 서버 연동은 별도로 확인해야 합니다.

화면 주소는 `/login`, `/events`, `/events/{event_id}`, `/events/{event_id}/report`, `/events/{event_id}/report/complete`입니다. 인증이 필요한 이벤트로 접근하면 로그인 뒤 해당 이벤트를 다시 조회합니다. D-09(#39, 결정 문서 v2.14)에 따라 실제 토큰과 데모 인증·데이터는 현재 탭의 `sessionStorage`에 저장합니다. 같은 탭의 새로고침에는 로그인이 유지되고 탭을 닫으면 세션이 종료됩니다. 서버의 토큰 유효기간 7일과 별개이며 로그아웃·보호된 API의 401에서 현재 탭의 토큰을 삭제합니다. 다른 탭의 로그인·로그아웃을 동기화하지 않습니다. 기존 `localStorage`의 실제 토큰은 삭제하며 자동으로 이전하지 않으므로 기존 사용자는 다시 로그인해야 합니다. 텔레그램 내 브라우저와 일반 브라우저의 저장소는 별개이므로 브라우저가 바뀌면 재로그인이 필요할 수 있습니다.

목록의 행동명은 `SUSPECT + INTRUSION_ATTEMPT`일 때만 생략합니다. 날짜 필터의 `from`과 `to`는 모두 `+09:00` 초 단위이며 종료일 다음날 0시를 미포함 경계로 보냅니다. 신고 중 `409 REPORT_ALREADY_EXISTS`·`RESPONSE_LOCKED`가 오면 상세로 이동해 최신 신고·잠금 상태를 다시 조회하고 안내합니다.

기준 문서는 작업 루트의 `docs/화면 목록 및 사용자 흐름 정의 v0.9.md`, `docs/villa-guard-front-UIUX-작업-기준.md`와 `villa-guard/docs/openapi.yaml`입니다. U07 텔레그램 설정과 운영자 화면은 이번 FE-3 범위에 포함하지 않습니다.

후속 일정은 FE-3 PR #72의 11/9 머지, FE-4 Must A01·A08의 11/9~11/12 구현·연동(최종 마감 11/15), FE-5 주민 API·텔레그램 링크 U04 진입의 11/12~11/14(마감 11/14)입니다. U03 목록 API는 11/11, U04 상세·응답·신고 API는 11/12 제공 예정이며 지연 시 바로 공유합니다. A06·A07은 1차 통합 이후의 Should입니다. U07 연결 시작의 `503 SERVICE_UNAVAILABLE`는 연결 불가 안내·재시도, `409 TELEGRAM_ALREADY_LINKED`는 상태 재조회·해제 후 재연결 안내로 처리하는 요구사항이며 U07 구현 시 적용합니다.


## 데모 데이터 초기화

현재 앱을 연 탭의 개발자 도구 Console에서 아래 코드를 실행하면 데모의 열람·응답·신고 변경 기록을 초기 예시 데이터로 되돌립니다. 로그인은 유지하며 실제 서버 데이터는 변경하지 않습니다.

```js
sessionStorage.removeItem('villa-guard-demo-events');
window.location.assign('/events');
```

초기 예시에는 검토 완료 신고가 있는 이벤트도 포함되어 있습니다. 신고 흐름은 목록의 첫 번째 미신고 이벤트로 다시 확인합니다. 새로고침이나 로그아웃만으로는 데모 이벤트 기록을 초기화하지 않습니다.

## FE-5 조기 착수 · 2026-11-09

기존 11/12 시작 예정에서 앞당겨 주민 API 연동과 텔레그램 알림 링크 진입을 점검합니다. U07 계정 연결·설정과 운영자 화면은 이번 작업에 추가하지 않습니다. 작업·검증 상세는 팀 저장소의 `docs/fe5-integration.md`에 기록합니다.

실제 로그인에서는 기존 API 호출 코드를 그대로 사용합니다. #79에서 안내한 U03 목록 응답의 `zone_id`를 유지하며 `viewed`는 ‘내 열람’, `confirmed`는 ‘세대 응답’, `response`는 ‘현재 응답’으로 표시합니다. FE가 열람 여부나 세대 응답을 임의로 계산하지 않습니다. BE-10 상세 API가 열람을 기록하기 전에는 샘플 열람 기록이 없는 이벤트가 모두 미열람으로 보일 수 있습니다.

텔레그램 링크는 `{FRONT_URL}/events/{event_id}`입니다. 기존 로그인은 상세로 바로 진입하고, 미로그인·토큰 만료 시에는 대상 이벤트 경로를 유지해 로그인 후 상세로 돌아갑니다. 로그인 화면에 복귀 안내를 표시합니다. 다른 세대·없는 이벤트는 상세 API의 403·404를 따릅니다. `/#event={event_id}` 형식의 이전 링크도 지원합니다.

실제 서버 점검은 Node 22 이상에서 실행합니다. `.env.example`을 `.env.local`로 복사한 뒤 `API_PROXY_TARGET`과 `VILLA_API_TOKEN` 또는 `VILLA_LOGIN_ID`·`VILLA_LOGIN_PASSWORD`를 설정합니다. 이 변수들은 `VITE_` 접두사를 쓰지 않아 브라우저 번들에 포함되지 않습니다.

```bash
# U03이 제공되면: 로그인/내 정보/목록/열람 필터
npm run check:api
# BE-10이 제공되면: 첫 목록 이벤트의 상세·열람 시각도 확인
npm run check:api -- --detail
```

특정 알림 이벤트는 `VILLA_EVENT_ID`로 지정합니다. 상세 검사는 API를 통해 본인 열람을 기록합니다. 상황 응답·오탐 신고는 제출하지 않으며 토큰·비밀번호·응답 본문은 출력하지 않습니다. 빈 목록만 있는 경우 카드 필드 검증은 데이터가 준비된 뒤 다시 실행해야 합니다.

2026-11-09 확인: 린트·프로덕션 빌드 통과, 자동 검사 25개 통과, 실제 React 번들과 모의 API를 사용한 DOM 시나리오 9개 통과 및 콘솔·런타임 오류 0개. `localhost:8080`은 연결되지 않아 실제 Spring Boot 서버·DB·영상·텔레그램 앱 검증은 남아 있습니다. DOM 검사는 실제 브라우저 화면·터치·영상 재생 검증을 대신하지 않습니다.
